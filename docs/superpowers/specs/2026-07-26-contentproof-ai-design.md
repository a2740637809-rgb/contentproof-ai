# ContentProof AI 设计规格

## 1. 项目目标

ContentProof AI 是一个面向内容运营场景的 AI 内容生产与质量评测工作台。项目用于把张作朋已有的内容运营经历转化为可运行、可复现、可量化的求职作品。

产品不以“一键生成文章”为卖点，而是展示完整证据链：

1. 录入业务目标与事实来源。
2. 按步骤执行 AI 内容工作流。
3. 检查生成内容的事实依据与业务适配度。
4. 比较不同 Prompt 或模型版本。
5. 记录人工终审决定与修改原因。
6. 输出可复现的评测报告。

## 2. 目标用户与使用场景

### 2.1 主要用户

- AI 产品运营、AI 应用运营或内容运营候选人。
- 需要评估候选人 AI 工作流与数据闭环能力的招聘者。
- 希望比较 Prompt 版本的内容编辑人员。

### 2.2 核心场景

- 基于结构化事实材料生成新闻、活动报道或平台改写稿。
- 检查人物、机构、时间、地点和数字是否有来源支持。
- 比较 Prompt A 与 Prompt B 在同一测试集上的表现。
- 查看人工修改前后的差异和常见失败原因。
- 导出供作品集展示的实验报告。

## 3. 首版范围

### 3.1 包含功能

1. 任务录入。
2. 来源与事实卡片管理。
3. 事实摘要、内容提纲、初稿和平台改写四步工作流。
4. Prompt 模板及版本管理。
5. Ollama 本地模型调用。
6. 确定性规则评测。
7. 模型辅助评分。
8. 人工接受、修改、驳回和原因标注。
9. 版本对比与基础数据看板。
10. Markdown 评测报告和 CSV 实验数据导出。

### 3.2 不包含功能

- 用户注册、登录与团队权限。
- 自动发布到公众号或内容平台。
- 云端模型账户和计费系统。
- 多智能体协作。
- 自动红队与安全扫描平台。
- 完整 RAG 知识库。
- 商业化订阅和支付。

## 4. 信息架构与页面

采用“编辑运营台”布局。

### 4.1 左侧导航

- 任务概览
- 来源资料
- Prompt 版本
- 评测报告
- 项目设置

### 4.2 中央工作区

- 显示事实摘要、内容提纲、初稿和平台改写的步骤状态。
- 展示当前步骤的输入、输出、耗时和模型信息。
- 支持从失败步骤重试。
- 支持将结果送交人工终审。

### 4.3 右侧质量面板

- 总分及五个维度得分。
- 无来源事实和风险提示。
- 评分理由。
- 人工终审操作。

## 5. 数据流

1. 用户创建任务并填写目标平台、受众、语气、事实材料和限制条件。
2. 系统把来源材料拆分为结构化事实卡片。
3. 工作流逐步生成事实摘要、提纲、初稿和平台改写稿。
4. 每一步保存输入、输出、Prompt 版本、模型参数、耗时和状态。
5. 评测引擎执行规则检查和模型辅助评分。
6. 用户接受、修改或驳回结果，并记录原因标签。
7. 系统把人工修改、评分和失败案例关联到对应运行版本。
8. 报告模块汇总版本差异、指标和结论。

任何步骤失败时，已完成步骤保持不变。用户可以从失败步骤重试，不重新执行整条任务。

## 6. 核心模块

### 6.1 任务模块

负责创建和读取内容任务。任务字段包括：

- 标题
- 内容类型
- 目标平台
- 目标受众
- 语气
- 字数范围
- 禁用表达
- 当前状态
- 创建与更新时间

### 6.2 来源模块

负责保存原文链接、来源名称、发布日期、短摘录和事实卡片。每张事实卡片包括：

- 事实文本
- 来源记录
- 事实类型
- 是否必须出现在成稿中
- 人工确认状态

### 6.3 Prompt 模块

每个 Prompt 版本不可覆盖修改。新版本保存：

- 模板名称
- 版本号
- 模板正文
- 适用步骤
- 创建时间
- 变更说明

### 6.4 工作流模块

首版使用显式状态机，不引入复杂编排框架。步骤状态为：

- pending
- running
- completed
- failed
- superseded

工作流步骤之间通过结构化 JSON 传递数据，避免依赖自由文本解析。

### 6.5 模型适配层

定义统一模型调用接口，首版实现 Ollama 适配器。适配层返回：

- 输出文本
- 结构化输出
- 模型名称
- 推理参数
- 开始与结束时间
- 错误信息

本机已有 `qwen2:1.5b` 和 `qwen2.5:0.5b`，可用于流程验证。界面必须提示小模型评分仅供辅助，不把模型评分表述为客观事实。

### 6.6 评测模块

评测由三层组成：

1. 确定性规则。
2. 模型辅助评分。
3. 人工终审。

每项评分必须保存分数、理由、阈值、通过状态和评分来源。

### 6.7 报告模块

支持：

- 单次运行评测报告。
- Prompt 版本横向对比。
- 测试集汇总。
- 常见错误统计。
- Markdown 和 CSV 导出。

## 7. 评测体系

总分 100 分：

| 维度 | 权重 | 判断内容 |
|---|---:|---|
| 事实准确性 | 35 | 人物、机构、时间、地点和数字是否得到来源支持 |
| 结构完整性 | 20 | 标题、导语、主体、背景和必要引语是否完整 |
| 可读性 | 20 | 表达是否清晰、简洁，是否存在重复或模板化语言 |
| 平台适配 | 15 | 长度、语气和结构是否符合目标平台 |
| 风险控制 | 10 | 是否出现无来源结论、敏感信息或禁用表达 |

### 7.1 确定性规则

- 必填字段检查。
- 字数范围检查。
- 禁用表达检查。
- 已知数字、日期、人物和机构名称覆盖检查。
- 输出 JSON 结构检查。

### 7.2 模型辅助评分

- 使用固定评分表。
- 强制返回符合 JSON Schema 的结构。
- 每个分数必须附带理由。
- 无法解析时标记失败，不使用默认高分。

### 7.3 人工终审

终审结果为接受、修改或驳回。人工修改分数或结论时必须选择原因标签并允许补充说明。

## 8. 真实作品与版权边界

首版使用以下四篇公开署名作品作为真实样本来源：

1. 《常德市老干部开展集中学习》
2. 《常德市新媒体协会成立》
3. 《“反诈+禁毒”遇上端午节》
4. 《好戏连台！常德银发人才闪耀校园文化艺术节》

公开仓库只保存：

- 标题
- 署名
- 发布日期
- 来源
- 原文链接
- 平台公开浏览量及采集时间
- 必要短摘录
- 自行制作的事实卡片和评测标注

公开仓库不保存完整新闻正文、原图或本地抓取缓存。完整正文可以在本地开发环境中临时读取，但不得提交到 Git。

页面浏览量只能表述为平台公开展示的累计口径，不表述为独立用户数。

## 9. 测试数据集

首版测试集不少于 20 条：

- 4 条真实署名作品任务。
- 至少 12 条基于公开资料制作的内容任务。
- 其余样本用于边界和失败测试。

每条测试样本包含：

- 任务要求
- 事实卡片
- 来源链接
- 必须覆盖的信息
- 禁止生成的信息
- 目标平台
- 人工参考结果或评分要点

## 10. 技术架构

### 10.1 前端

- React
- TypeScript
- Vite

### 10.2 后端

- Python
- FastAPI
- Pydantic

### 10.3 数据存储

- SQLite
- 数据访问层与业务逻辑分离

### 10.4 模型

- 默认 Ollama
- 统一 Provider 接口允许后续增加其他模型
- 密钥只从环境变量读取

### 10.5 借鉴原则

- 借鉴 Promptfoo 的多版本横向比较。
- 借鉴 Phoenix 的运行追踪与实验记录。
- 借鉴 DeepEval 的测试用例、阈值和评分理由。
- 借鉴 LangGraph 的状态化流程与人工介入思想。
- 借鉴 Ragas 的忠实度和相关性评测思路。

首版不复制这些项目的界面或源代码，也不引入不必要的重量级依赖。

## 11. 错误处理

- Ollama 未运行：显示检测结果和启动提示，不删除任务。
- 模型不存在：列出本机可用模型并允许重新选择。
- 模型超时：保存失败状态、错误类型和已完成步骤。
- JSON 输出无效：保留原始输出并允许重试。
- 来源链接失效：保留原记录并标记待人工核验。
- 导出失败：不影响任务和评测数据。

错误信息不得包含密钥、完整环境变量或其他敏感数据。

## 12. 测试策略

### 12.1 后端自动化测试

- 状态机正常流转与失败恢复。
- Prompt 版本不可覆盖。
- 评分权重和总分计算。
- 确定性规则。
- 模型结构化输出解析失败。
- SQLite 数据保存与读取。
- 报告导出。

### 12.2 前端测试

- 创建任务。
- 查看工作流步骤。
- 查看评分理由。
- 完成人工终审。
- 比较两个 Prompt 版本。

### 12.3 手工验收

- 使用本机 Ollama 完整运行一条任务。
- 对至少两个 Prompt 版本运行同一批样本。
- 检查导出的 Markdown 和 CSV。
- 确认公开仓库不包含密钥、完整新闻正文和数据库文件。

## 13. 首版验收标准

- 4 篇真实署名作品建立公开元数据记录。
- 测试集不少于 20 条。
- 至少两个 Prompt 版本完成对比。
- 工作流可完整运行并保存中间结果。
- 失败步骤可以重试。
- 可以查看来源覆盖、评分明细和人工修改差异。
- Ollama 离线运行成功。
- 可以导出 Markdown 和 CSV。
- 核心逻辑自动化测试通过。
- README 能够让招聘者理解、安装并复现实验。
- Git 仓库不包含密钥、完整新闻正文、原图或本地数据库。
