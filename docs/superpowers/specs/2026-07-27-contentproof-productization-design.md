# ContentProof AI 产品化升级设计

**日期：** 2026-07-27  
**状态：** 待用户书面复核  
**目标：** 将当前静态作品集原型升级为可公开体验、可本地运行、可完成真实内容质量实验的开源产品。

## 1. 产品定位

ContentProof AI 是面向内容运营、编辑、AI 应用运营和独立开发者的 AI 内容质量实验室。它不与通用工作流平台竞争，而是专注于一条明确闭环：

> 来源资料 → 事实卡 → 内容生成 → Prompt 对照 → 批量评测 → 人工终审 → 证据报告

产品同时提供：

- **公开演示模式：** 无需模型和密钥，预载完整案例，访客可立即操作。
- **本地真实模式：** 连接 Ollama，执行真实生成和评测，数据保存在本机。

所有示例结果必须标注“演示数据”，不得伪装成实时模型结果。

## 2. 高星项目借鉴

### Dify

借鉴首次使用向导、模型连接诊断、工作流可视化、节点级运行状态和失败重试。ContentProof 不实现通用拖拽编排，只保留内容生产所需的固定四步工作流。

参考：https://github.com/langgenius/dify

### Langfuse

借鉴 Prompt 不可变版本、运行 Trace、数据集、实验记录、指标与人工标注。ContentProof 的 Trace 以任务和四个内容步骤为中心。

参考：https://github.com/langfuse/langfuse

### Promptfoo

借鉴测试用例、断言、批量评测、失败原因、模型与 Prompt 横向比较。ContentProof 将通用 LLM 断言收敛为事实、篇幅、禁用语、平台适配和风险控制。

参考：https://github.com/promptfoo/promptfoo

## 3. 用户入口

首页提供两个主入口：

1. **立即体验示例**
   - 载入预置项目、公开来源、事实卡、Prompt v1/v2、实验结果和审核记录。
   - 所有筛选、编辑、比较、审核和导出操作可用。
   - 模型生成操作使用固定演示输出，并显示“演示结果”标签。

2. **连接本地模型**
   - 检测后端、SQLite 和 Ollama 状态。
   - 列出已安装模型。
   - 用户选择模型后进入真实模式。
   - 连接失败时显示原因、修复命令和重试按钮。

## 4. 信息架构

### 4.1 项目概览

- 最近运行记录
- 评测通过率
- 平均分及五维分布
- 高频失败原因
- 当前模型和运行模式
- “新建实验”和“继续上次运行”操作

### 4.2 来源资料库

- 添加网址或粘贴文本
- 查看来源标题、URL、短摘要、版权说明和采集时间
- 编辑事实卡
- 标记已核验、待核验或驳回
- 搜索和按状态筛选
- 不在公开仓库保存新闻全文或原图

首版不自动抓取任意网页正文。网址导入只保存用户提供的元数据和短摘要，避免版权与反爬问题。

### 4.3 内容工作流

固定步骤：

1. 事实提取
2. 内容提纲
3. 初稿生成
4. 平台改写

每一步展示：

- 输入
- 输出
- 状态
- 模型
- 耗时
- 错误信息
- 单步重试

已完成步骤的输出在后续步骤失败时保持不变。用户可以编辑输出后继续下一步。

### 4.4 Prompt 实验

- 查看 Prompt 名称、版本、模板和变更说明
- 基于旧版本创建新版本，不允许覆盖历史版本
- 选择测试集和模型
- 批量运行案例
- 对比 v1/v2 输出、得分、耗时、规则通过情况和人工决定
- 按失败案例筛选

### 4.5 评测中心

确定性检查：

- 必需事实是否出现
- 禁用语是否命中
- 篇幅是否合规
- 来源是否存在

辅助评分：

- 事实准确性 35%
- 结构完整性 20%
- 可读性 20%
- 平台适配 15%
- 风险控制 10%

评测页面必须显示逐项理由和失败证据，不能只显示总分。模型分数始终标注“辅助评分，仅供参考”。

### 4.6 人工审核与报告

- 接受、修改或拒绝
- 原因标签与备注
- 可编辑最终稿
- 导出 Markdown 报告
- 导出 CSV 实验表
- 导出 JSON 证据包

报告包含任务约束、来源链接、Prompt 版本、运行步骤、规则结果、辅助评分和人工决定。

## 5. 界面结构

### 桌面端

```text
┌────────────┬──────────────────────────────────────┐
│ 产品导航   │ 页面标题 / 模式 / 模型 / 全局操作   │
│            ├──────────────────────────────────────┤
│ 概览       │                                      │
│ 资料库     │ 当前页面主内容                       │
│ 工作流     │                                      │
│ 实验       │                                      │
│ 评测       │                                      │
│ 审核       │                                      │
│            ├──────────────────────────────────────┤
│ 连接状态   │ Toast / 任务进度 / 错误恢复          │
└────────────┴──────────────────────────────────────┘
```

不再使用始终占据三分之一宽度的静态评分侧栏。评分作为评测页面和运行详情的一部分出现，使主工作区获得足够空间。

### 移动端

- 顶部模式与连接状态
- 底部标签导航
- 表格转换为案例卡片
- 主操作固定在页面底部但不遮挡内容
- 不依赖横向滚动完成核心操作

## 6. 系统架构

### 前端

- React + TypeScript + Vite
- 基于路由或页面状态的六模块界面
- 统一 API 客户端
- 统一 loading、empty、error 和 toast 状态
- 演示模式适配器与真实 API 适配器使用相同接口

### 后端

- FastAPI + SQLAlchemy + SQLite
- 补充列表、详情、更新、删除与实验查询 API
- 工作流执行使用后台任务状态，前端轮询运行进度
- Ollama 调用保持在 ModelProvider 接口之后
- 演示数据通过幂等种子脚本加载

### 部署

- 在线演示部署为静态前端，默认使用演示模式
- 本地完整版运行 FastAPI、SQLite 和 Ollama
- 在线演示不调用用户本地 Ollama，也不保存敏感内容

## 7. 数据流

### 演示模式

```text
预置 JSON → DemoRepository → React 页面 → 浏览器内临时修改 → 下载报告
```

刷新页面可重置示例。页面明确显示“演示模式”。

### 真实模式

```text
React → FastAPI → SQLite
                 ├→ RuleEngine
                 ├→ EvaluationService
                 └→ OllamaProvider → 本地 Ollama
```

前端创建任务后依次创建来源、运行工作流、轮询步骤、发起评测并提交人工审核。

## 8. 错误处理

- 后端不可用：显示启动命令和“重新检测”。
- Ollama 不可用：允许切换演示模式，不丢失已录入内容。
- 模型缺失：显示已安装模型和 `ollama pull` 命令。
- JSON 输出异常：保存原始响应，标记失败步骤并允许重试。
- 来源缺失：阻止真实运行并指出缺少哪项资料。
- 导出条件不足：列出尚未完成的评测或审核步骤。
- 所有错误必须说明下一步操作，不显示模糊的“发生错误”。

## 9. 测试与验收

### 后端

- CRUD API 测试
- 演示种子幂等测试
- 四步执行与失败重试测试
- 评测理由与证据测试
- 审核和三种导出测试

### 前端

- 首页双入口测试
- 模式切换测试
- 新建任务与来源测试
- 运行进度和失败重试测试
- Prompt 对照筛选测试
- 审核与下载测试

### 端到端

至少覆盖：

1. 无 Ollama 的演示模式完整流程。
2. 有 Ollama 的真实任务完整流程。
3. 模型不可用时切换演示模式。

### 产品验收

- 首次访问者在 30 秒内能开始示例。
- 所有可见按钮具有真实行为或明确禁用原因。
- 用户能在一个会话内完成创建、运行、评测、审核和导出。
- 演示结果与真实结果不会混淆。
- 桌面和 390px 移动宽度无裁切。
- README 提供在线体验、30 秒启动、功能矩阵、架构图、截图、路线图和贡献说明。

## 10. 明确不做

首轮升级不包含：

- 通用拖拽节点编辑器
- 用户登录与多租户
- 多人实时协作
- 插件市场
- 自动发布到内容平台
- 云端模型计费
- 任意网页全文抓取

这些功能会稀释内容质量实验室的定位，并显著增加交付风险。
